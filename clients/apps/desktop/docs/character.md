# Character animation

[← clients/desktop](../CLAUDE.md)

The character: the feed every surface reads, the driver seam every kind of character sits behind, the second window that shows it today, the 2D engine, and the editor that produces the configuration.

**The live feed is a store, not a wire** (#238). Everything a character reacts to is written into `@kurisu/state`'s `characterFeedStore` by its producer and read from there by whatever surface is showing: `useTTS` publishes one `SpeechSegment` per spoken sentence (the sentence's RMS curve, its own window length, and `startedAt` stamped on the audio element's `playing` event — never on the call to `play()`) plus a `SpeechSync` every 500 ms from `audio.currentTime`, and `null` when the queue drains; `useStreamingChat` sets `thinking`; `visionStore` pushes gesture bursts (each with a rising `seq`, so a surface takes a burst once and two surfaces cannot steal each other's) and sets the faces in view; `useCharacterPanel` keeps the personas in the conversation and who is speaking (the reactive half, zustand) and publishes subtitle events. Nothing is sampled at frame rate in the producer: a surface's own loop calls `sampleSpeech` (`@kurisu/models` `speechClock.ts`) against the segment and the last sync, interpolating the curve and slewing toward the sync at most 20 ms a frame — so hiding the main window to the tray, which throttles its timers, no longer stalls the mouth, and a phone's output latency is absorbed by the first sync. `resetCharacterFeed()` is silence.

**One driver contract, any surface.** `CharacterDriver` (`@kurisu/models` `characterDriver.ts`: `load`, `update(dtMs, DriverInput)`, `resize`, `dispose`) is what a surface holds; `CharacterSurface` (`@kurisu/ui/src/character/`) owns the box, a `ResizeObserver`, and the frame loop that samples the feed and calls `update`, and picks the driver by `character.kind`. Today only `PoseGraphDriver` exists — an adapter over the unchanged `CanvasCompositor` (the compositor keeps its own render loop; the adapter writes its three input fields, forwards gestures and faces, serialises loads so a newer one supersedes an older, turns a config it cannot draw into a readable rejection, and makes `dispose` idempotent). A VRM persona shows "No avatar" until #240 mounts `@kurisu/vrm` behind the same seam. The conformance cases in `@kurisu/vrm/testing` run over the adapter (`PoseGraphDriver.test.ts`), and `CanvasCompositor.test.ts` pins the engine's own behaviour with a recording context and a hand-stepped loop. A persona's character is reloaded when `characterFingerprint` (`@kurisu/models`) changes — the tree's content, or a VRM's model/clip digests and settings — not on object identity and not on counts, which is what let an image edit go unnoticed before.

Separate Electron window, opened and closed by the Face icon on the chat header or by `/live-animate` — both dispatch `kurisu:toggle-character`, and both need `capabilities.characterWindow`: the button is not rendered without it, and the command answers "This host has no character window." instead of dispatching. `ChatPanel` is the one owner of the open/closed state: it flips before `open()` resolves, so the feed to the window is on before the window can ask for it, `onWindowClosed` flips it back, and a `ready` from the window flips it on — which is what re-syncs a main renderer whose idea of the window is stale. (Nothing opened the window at all between the layout rewrite and #237; the docs said "Face icon in top bar" about a button that no longer existed.) **A reload of the main renderer closes the window** (`did-start-navigation` in `electron/main.ts`): the reloaded renderer would otherwise start with no memory of a window that lives on holding a token nobody refreshes; the next toggle opens a fresh one. Opens as independent, resizable (aspect-ratio-locked 2:3) frameless BrowserWindow — same Vite bundle routed via `?window=character` query param → `CharacterWindowApp` (no login and no stores of its own, purely IPC-driven). Default 512×768, min 256×384.

**It has no session of its own.** The asset routes are bearer-only, and a second renderer has its own empty copy of `storage`'s token memory, so the main renderer pushes the access token over `character:session` (below) and the window fetches nothing until the first push has arrived — even one saying there is no session. A null push clears its image cache and shows "Signed out"; `authStore.logout` pushes null and closes the window.

**IPC channels** (every one relayed by the main process, which inspects none of them; the direction is given per channel). The window is a second renderer with its own copy of the feed store: the main renderer's `useCharacterBridgeSync` (mounted in `ChatPanel`, the owner of the open/closed state) mirrors every feed write over these channels while `windowOpen` is set, and the window writes each message into its store, from which its `CharacterSurface`s read exactly as an inline panel would (#241). Nothing crosses at frame rate.
- `character:ready` — character window → main renderer, once the window's listeners are subscribed. Answered with `character:session`, then `character:personas-update`, then what the feed holds right now (`character:feed`, `character:face-update`, `character:speech`, and a `character:speech-sync` if one is pending) so a window opened mid-sentence catches up. The main renderer's handlers for this and for `character:session-request` are subscribed regardless of what it believes about the window, because a `ready` is proof the window exists — and a `ready` sets `windowOpen`.
- `character:speech` — main renderer → character window: a `SpeechSegment` when a sentence's audio begins, `null` when speech ends. One message per sentence.
- `character:speech-sync` — main renderer → character window: `{ positionMs, at }`, the producer's real playback position, every 500 ms while a sentence plays.
- `character:feed` — main renderer → character window: `{ isThinking }` on change.
- `character:personas-update` — main renderer → character window: `{ personas: [{id, name, avatarUuid, character}], activePersonaId }` on persona map or active persona change; `character` is the parsed config, whatever its kind
- `character:gesture-update` — main renderer → character window: `{ gestures: string[], seq }`, one burst from the vision pipeline
- `character:face-update` — main renderer → character window: `{ faces: string[] }`, the identities currently in view, level state for `face` conditions
- `character:subtitle` — `{ text: string, isUser: boolean, duration?: number }` subtitles displayed as overlay at bottom of character window, by `SubtitleQueue` (`@kurisu/ui/src/character/subtitleQueue.ts`, a pure module the inline panel will share). Assistant text: `sentenceDuration = chunkDuration / sentenceCount` (chunk split on `.!?。！？\n`). TTS success → chunkDuration = WAV duration; TTS error → chunkDuration = 4s. Sentences queued and shown sequentially, chaining immediately, fade only after last. User text shown immediately with word-count-based hold. Empty text clears (cancel).
- `character:session` — `{ accessToken }` main renderer → character window, sent from `storage.setToken`, `clearToken` and `clearTokens` (so a login, a refresh and a sign-out all reach it) and first thing on `character:ready`, **before** `character:personas-update`. Only ever the access token — never the refresh token. The window takes it with `storage.adoptToken`, never `setToken`: `persistTokens` writes both fields from that window's memory, and a window holding no refresh token would null the persisted one.
- `character:session-request` — character window → main renderer: an asset fetch came back 401. The main renderer refreshes (which re-pushes through `storage.setToken`) or, with nothing to refresh, re-sends what it holds so the window's wait ends. `fetchAuthedBlob`/`fetchAuthedBytes` in `@kurisu/api` is the one authenticated fetch on both sides — the image cache, the compositor's videos and `useAuthedAssetUrl` all go through it — and retries exactly once with whatever the renderer's configured refresher returns (`apiClient.tryRefresh` in the main window, the request round trip in the character window). **It sends the bearer to the backend's origin only**: a pose tree may carry an absolute URL, and a foreign host is fetched plain, with no retry on its 401. The window waits at most 10 s (`SESSION_REQUEST_TIMEOUT_MS` in `CharacterWindowApp.tsx`) for the next `character:session`; on expiry the retry is skipped, the 401 stands, and the asset is reported as failed to load — the window does not sign out. A load that failed is retried once the next session carrying a token arrives (`CharacterSurface`'s `retryToken`); a load that succeeded ignores a routine refresh.
- `character:window-closed` — main process → main renderer when user closes character window
- `character:open-window` / `character:close-window` — renderer invokes main process to create/destroy window

**Canvas compositing**: Base image + diff patches (eyes, mouth) at stored positions. Blink: configurable random interval state machine (default 2-6s). Breathing: sine wave vertical offset (configurable amplitude/period). Lip sync: audio amplitude → mouth patch index. Per-persona character configs stored in backend DB as JSON. **State machine**: IDLE (blink/breathing/mouth + event listening) → TRANSITIONING (playing edge video on canvas, all events ignored) → IDLE (switch to target pose, apply node settings, reset timers). During transitions no events are processed; random timers start fresh when arriving at a node. **Multi-transition edges**: Each directed edge (`AnimationEdge`) contains `transitions: EdgeTransition[]` — multiple transitions per edge, each with its own condition, video list, and playback rate. One edge per directed node pair (ID: `{source}-{target}`). Timer keys use `${edge.id}:${transitionIndex}`. Legacy edges (single condition/video_urls/playback_rate) auto-migrated on load via `migrateEdgeToTransitions()`. Legacy IDs (`pose-*`/`edge-*`) auto-migrated to 8-char random hex via `migratePoseTreeIds()` (calls `POST /character-assets/{persona_id}/migrate-ids` to rename files on disk). Bidirectional edges render side-by-side with perpendicular offset (not overlapping). Transition conditions: `random` (timer-based), `thinking` (fires when `isThinking` matches `condition.value`), `gesture` (fires when a detected gesture matches `condition.value`, e.g. "wave", "thumbs_up", "peace_sign"), `face` (fires while the named identity is, or is not, in view). `isThinking` and faces are live variables observed each frame while idle — no edge detection; a gesture is consumed by the tick that sees it. **Transitions are evaluated in edge order and the first whose conditions all hold wins** — never a random choice among matches — and an instant (video-less) transition returns to idle synchronously, so a level-triggered edge can chain several hops inside one frame (`CanvasCompositor.test.ts` pins both). **Per-node animation settings**: `AnimationNode.animation_settings` (optional) configures breathing (enabled/amplitude/period) and blink timing (min/max interval, close/hold/open duration). Applied via `applySettings()` on each pose switch. UI: sliders in PoseNodeEditor Preview step.

**Asset pipeline**: AI-generated base → inpainted variants → backend OpenCV diff → cropped patch PNGs. Assets stored in folder structure: `data/character_assets/{persona_id}/{pose_id}/base.png`, `{part}_{index}.png`; videos in `{persona_id}/edges/{edge_id}.mp4|.webm`. Re-uploading overwrites without changing URLs. Orphaned assets cleaned up on config save.

**Config shape** (`@kurisu/models` `character.ts`, wire protocol 7, #235): `character_config` is `{ kind: 'pose_graph' | 'vrm', pose_tree?, vrm? }` — `kind` selects what renders and the two members coexist, so switching back needs no upload. `parseCharacterConfig()` is the one reader (`{ kind, poseTree, vrm }`, null for anything without a recognised `kind`; there is no kind-less fallback, the backend stamps every row). A save is a merge per member: the graph editor sends `{ kind, pose_tree }` with the kind it loaded and never touches `vrm`; a member left out is kept server-side, `null` clears it. Only pose graphs render today — a `vrm` persona reads as "No avatar" in the window until #240, "3D model" on its settings card.

**Data flow**: `useCharacterPanel` fetches a persona's character_config (via `GET /personas/{id}`) the first time that persona appears while a surface is showing (`inlineVisible || windowOpen`), again when it starts speaking, and again when the editor saves → `parseCharacterConfig` → `useCharacterStore.setPersona` (kept by identity when the fingerprint, name and avatar are unchanged) + `activePersonaId`. `useCharacterBridgeSync` mirrors the store and the feed to the window; `CharacterWindowApp` writes what arrives into its own store and renders one `CharacterSurface` per persona; the surface's `PoseGraphDriver` calls `compositor.loadPoseTree()` to load all poses + initialize edge timers, and its frame loop hands the compositor the sampled amplitude, thinking, gestures and faces each frame.

**Graph editor (CharacterConfigDialog)**: reached from Settings → Personas → a persona → "Edit character graph"; it takes a `persona` and keys every asset path by that persona's id. React Flow (@xyflow/react) canvas with custom `poseNode` nodes. Nodes represent poses; one edge per directed node pair containing multiple transitions. Connecting an existing pair opens the edge editor instead of creating a duplicate. Sub-dialogs: PoseNodeEditor (3-step stepper for base/patches/preview), EdgeEditor (multi-transition cards with per-transition condition/video/playback rate). Right-click node for context menu (Toggle Default, Edit, Delete). Multiple nodes can be marked as default (`default_pose_ids: string[]`); one chosen randomly at runtime. Conversion: poseTreeToReactFlow/reactFlowToPoseTree. Video upload naming: `${edge.id}_t${transitionIdx}_${videoIdx}`. Each debounced auto-save also fires a `character-config-saved` window event carrying `{ personaId }` — `useCharacterPanel` listens for exactly that key to re-fetch the pose tree, so renaming it silently stops the live character window from picking up edits.

**Emotion channel** (#243, what arrives; applying it to a face is #244): for a persona whose character is a VRM model with `vrm.emotion.enabled`, the backend asks the model to tag a sentence whose feeling changes, strips the tag, and forwards a *cue*. On the stream it is `emotion` / `emotion_at` on the `stream_chunk` whose `content` starts at that point (`@kurisu/api` `websocket.ts` `StreamChunkEvent`); in the history it is `Message.emotion_cues`, the whole list in order (`@kurisu/models` `EmotionCueRecord { emotion: VrmEmotion; at: number }` — the recorded cue; the `EmotionCue` a driver is fed carries a hold and a weight instead, see `characterDriver.ts`). `emotion` is one of the six VRM preset names; `at` is an offset into the accumulated assistant text of that LLM round in UTF-16 code units — `String.length`, so `accumulatedContent.slice(at)` is exact and an emoji before the tag counts two. A tool call starts a new round and a new message, and the offsets restart at 0. Nothing in this client reads the fields yet: `useStreamingChat` builds the streamed `Message` from a fixed list of fields and copies neither `emotion` nor `emotion_at` into it, so a bubble that is still streaming carries no cues; only a conversation loaded from history has `emotion_cues`. Text streams seconds ahead of speech, so the cue must be applied when the sentence is *spoken*, not when its chunk arrives — collecting the cues off the stream and that timing are both #244. The reloaded conversation's last cue is what will set the resting face. Lip sync itself stays amplitude-only: `POST /tts` returns a WAV with no timings or phonemes, so there is nothing else to drive the mouth with. The mock backend's `emotion` scenario carries cues on the chunks and in the history. Nothing here reaches the voice: the viXTTS `emo_audio` / `emo_alpha` / `use_emo_text` request fields and the "Emotion Controls" in Settings → TTS were removed in the same change — the backend's `POST /tts` never declared them at any revision (`backend/docs/tts.md`).
